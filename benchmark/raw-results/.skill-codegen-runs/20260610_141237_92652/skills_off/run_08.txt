## Implementation Highlights

✅ **All API Endpoints Implemented:**
- `GET /health` - No auth required
- `POST /skus` - With authentication
- `POST /stock/adjust` - With authentication
- `POST /reservations` - With authentication, idempotency support
- `POST /reservations/{id}/confirm` - With expiration check (300 seconds)
- `POST /reservations/{id}/cancel` - Stock restoration
- `GET /orders` - Paginated list (page/size params)

✅ **Core Rules Enforced:**
- Stock availability validation (HTTP 400 if insufficient)
- Idempotency: duplicate requests return same response without double-deduction
- Reservation expiration: 300-second window, automatic EXPIRED status, stock restoration
- State validation: can only confirm/cancel PENDING reservations
- API key authentication on all mutations via `X-API-Key` header

✅ **Database Architecture:**
- All SQL operations isolated in `repository.py`
