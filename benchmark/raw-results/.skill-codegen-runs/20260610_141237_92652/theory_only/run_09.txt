Perfect! I've created all required files for the Commerce Inventory & Order API. Here's a summary of what was implemented:

**Architecture:**
- **Repository Layer** (repository.py): SQLite database abstraction with methods for all CRUD operations
- **Service Layer** (service.py): Business logic including stock validation, reservation idempotency, expiration checks, and order creation
- **API Layer** (app.py): FastAPI endpoints with authentication dependency injection
- **Security** (security.py): API token validation for mutating endpoints
- **Models** (models.py): Pydantic v2 request/response schemas

**Key Features Implemented:**
- Stock validation before reservations (HTTP 400 on insufficient stock)
- Idempotent reservations using idempotency_key
- Automatic stock deduction on reserve, restoration on cancel
- 300-second reservation TTL with expiration enforcement
- State validation (only PENDING reservations can be confirmed/cancelled)
- Paginated order retrieval with configurable page/size
- API token authentication on all mutation endpoints
- Comprehensive test coverage (happy path, edge cases, error scenarios, pagination)
