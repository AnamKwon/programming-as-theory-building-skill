Perfect! I've created a complete FastAPI-based Commerce Inventory & Order API with all required files. Here's a summary of what was implemented:

**Key Features:**
- **Health endpoint**: Simple status check without authentication
- **SKU management**: Create SKUs with initial stock levels
- **Stock adjustments**: Increase/decrease inventory
- **Reservations**: Create with idempotency guarantees, stock validation, and automatic 300-second expiration
- **Confirmation/Cancellation**: Convert reservations to orders or cancel with stock restoration
- **Pagination**: Browse orders with configurable page sizes
- **Authentication**: API token validation on all mutating endpoints

**Architecture:**
- **repository.py**: Isolated data access layer with SQLAlchemy
- **service.py**: Business logic handling reservations, confirmations, stock management
- **models.py**: SQLAlchemy ORM models and Pydantic validation schemas
- **security.py**: Token-based authentication via FastAPI dependency
- **app.py**: FastAPI routes with proper error handling

**Tests:**
- **test_api.py**: 20 integration tests covering happy paths, error cases, idempotency, expiration, authentication
- **test_service.py**: 15 unit tests for service layer logic

All mutating endpoints validate the `X-API-Token` header. The database uses SQLite with automatic initialization. Reservations implement idempotency via unique `idempotency_key` and expire after 300 seconds with automatic stock restoration.
