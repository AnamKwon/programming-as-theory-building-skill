## Project Summary

I've built a production-grade commerce service with:

**Architecture:**
- Clean layering: API → Service → Repository → Database
- Dependency injection for testability
- Type hints throughout
- Pydantic validation on all inputs

**Key Features:**
- SKU management with stock tracking
- Idempotent reservation creation (prevents duplicates)
- Automatic reservation expiration (10 min TTL)
- Order confirmation with stock deduction
- Paginated order lookup
- API key authentication on mutations
- Comprehensive test coverage (happy paths + edge cases)

**Data Flow:**
1. Create SKUs with initial stock
2. Reserve stock (holds for 10 minutes, accounts for concurrent reservations)
3. Confirm reservation → creates Order and deducts stock
4. Or cancel before expiration

**Database:** SQLite with SQLAlchemy ORM (in-memory for tests, `./commerce.db` for dev)

All business rules are enforced at the service layer, and the repository pattern keeps data access clean and testable.
