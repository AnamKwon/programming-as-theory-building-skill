**Key design highlights:**

- **Layered Architecture**: API → Service (business logic) → Repository (database) boundary keeps concerns separated
- **Stock Safety**: Reservations don't deduct stock; confirmation creates immutable orders when ready
- **Idempotency**: Request deduplication via stored responses prevents duplicate orders
- **Expiration**: Reservations automatically expire after 15 minutes (configurable), blocking stale confirmations
- **Pagination**: Cursor-based (not offset-based) for stable ordering across inserts
- **API Key Auth**: All mutations require `X-API-Key` header validation
- **Clear Errors**: HTTP status codes map to domain failures (409 for stock conflicts, 410 for expired, 401/403 for auth)
