I have enough evidence. I inspected every source and test file, reproduced the core defect in isolation, and ran the full suite (36 failed, 3 passed). The findings are conclusive.

The decisive issue: `Repository._get_conn()` opens a fresh `sqlite3.connect(":memory:")` on every call, and each `:memory:` connection is a *separate* database. Tables created in `_init_db()` vanish when that connection closes, so every subsequent operation raises `no such table`. Since `app.py:34` and all test fixtures use the default `":memory:"`, the entire application is non-functional as shipped — only the 3 tests that never touch the DB (health, 401, 403) pass.
