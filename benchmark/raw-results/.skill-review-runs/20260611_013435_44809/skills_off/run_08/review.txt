Root cause confirmed. Here is my objective evaluation.

The implementation has a **fatal architecture bug**: `Repository._get_connection()` opens a fresh `sqlite3.connect(":memory:")` on every call. Each in-memory SQLite connection is an isolated database, so the tables created in `_init_db()` are destroyed when that connection closes. Every stateful operation fails with `no such table: skus`. Test result: **2 passed / 22 failed** (only `/health` and the auth-rejection test, which never touch the DB, pass).
