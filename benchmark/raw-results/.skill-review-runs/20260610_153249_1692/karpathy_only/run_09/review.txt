The two distinct runtime failures:
1. **12 API tests** fail with `sqlite3.OperationalError: no such table: skus` — the `Repository` uses thread-local connections against a `:memory:` SQLite DB. `_init_db()` runs only on the constructing thread; Starlette's `TestClient` serves requests on a different worker thread, which opens a fresh, empty in-memory database with no tables. The HTTP service collapses for every DB-backed endpoint.
2. **1 service test** (`test_confirm_reservation_success`) fails with `AttributeError: 'Repository' object has no attribute 'repo'` — a `service.repo.repo` typo in the test.

Also: the `reset_db` fixture reassigns the *test module's* globals, not `commerce_service.app`'s, so it never actually resets the app database (broken isolation).
