Key technical findings:
- **Broken dependency injection**: endpoints use `get_service()` (app.py:38-46) which directly instantiates `SessionLocal` bound to the file DB `commerce.db`. The `get_db_session` dependency (app.py:49) is never wired into any endpoint, so the test's `app.dependency_overrides[get_db_session]` (test_api.py:26) is a no-op. Tests run against a persistent `./commerce.db` file (confirmed created, 40KB) and leak state across tests.
- **2 failing tests**: `test_create_reservation_insufficient_stock` returns 201 instead of 409 because idempotency key `"key-1"` was already persisted by an earlier test in `commerce.db`; `test_list_orders_pagination` is self-contradictory (asserts 10 items while creating zero orders, total==0).
- **Missing order-creation endpoint**: `service.create_order`/`update_order_state` exist but no `POST /orders`; order state transitions are never reachable via the API.
- Dead code: `get_db_session`, `update_order_state`, `create_order`, `ErrorResponse`, `create_engine` import in models.py, unused `python-dotenv` dep; global exception handler returns a dict rather than a `Response`.
