All files read, tests executed, and the app smoke-tested. Here is my objective evaluation.

**Key runtime findings:**
- `tests/test_service.py`: 11/11 pass — the service/business layer is correct.
- `tests/test_api.py`: 2/16 pass, 14 fail. Two distinct root causes:
  1. **Broken test fixture (environment isolation):** the `db` fixture uses `create_engine("sqlite:///:memory:")` with the default `SingletonThreadPool`. Tables are created on the test thread's connection, but `TestClient` dispatches requests on a different thread, which gets a fresh empty in-memory DB → `OperationalError: no such table: skus`. The `test_confirm_reservation_expired` test compounds this by mutating via the file-based `SessionLocal` instead of the overridden session.
  2. **Auth semantics bug:** `verify_api_key` uses `Header(...)` (required), so a *missing* `X-API-Key` returns **422**, not the expected **401**. Invalid-key correctly returns 401.
- Direct smoke test against the real file DB confirms the app itself runs correctly: 201 on create, 400 on insufficient stock, idempotent duplicate returns cached reservation, pagination correct.
